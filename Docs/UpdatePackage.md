# Updating the xcproj Pkl package

`xcprojgen update-package [dir]` updates the `xcproj` dependency in an existing
`PklProject` and refreshes `PklProject.deps.json` using the Pkl CLI. The directory
defaults to the current directory. Use the directory containing `PklProject`.

```sh
brew upgrade giginet/xcproj/xcprojgen
xcprojgen update-package
xcprojgen validate
```

By default, the command selects the version of the running CLI, just like
`xcprojgen init`. This keeps the CLI and package on the same release and avoids
a separate latest-version lookup on GitHub. Pass `--to 0.2.0` to select a specific
release, including a downgrade. Accept stable `X.Y.Z` versions. Explicit pins
outside the CLI's release are allowed with a compatibility note.

## Supported manifests

The first version supports a literal `uri` in the `dependencies["xcproj"]`
object, using the release URL generated by `init`. It replaces the entire URI,
including both version segments, and preserves formatting, comments, and other
dependencies. Use a syntax-aware edit scoped to that property. An evaluated
manifest alone cannot tell us which source text to edit.

Reject ambiguous or unsupported definitions before writing anything, with the
manifest path and the target URI in the diagnostic. This includes computed URIs,
local package imports, and alternate hosts. A matching literal pin is eligible
for dependency resolution so the command can also create a missing lockfile.

## Resolution and failure behavior

1. Find `PklProject`, check that the existing pin can be edited, and determine
   the target URI. Check that Pkl is available using the CLI's existing lookup.
2. Save the original manifest and lockfile contents, including whether the
   lockfile existed. Write the edited manifest atomically and run
   `pkl project resolve` from the original project directory so relative
   imports and local dependencies keep their meaning.
3. If resolution fails, restore both files to their original state and report
   Pkl's error. If restoration itself fails, report which files need attention.
   These are two separate files, so an abrupt process termination may require
   recovering them from version control. Run the command while no other process
   is editing the manifest or resolving the same project.
4. Report the old and new versions and which files changed, or report that the
   project is already up to date. The command does not generate Xcode bundles.
   Run `xcprojgen validate` to check whether the project's configuration needs
   edits after a package upgrade.

Pkl owns the lockfile format. Resolution can update other entries according to
Pkl's dependency rules, so review both files together before committing.

## Acceptance checks

- The default command and an explicit version update the correct dependency,
  including a manifest with comments and unrelated dependency declarations.
- A matching pin can restore a missing lockfile. Repeating a successful update
  with the same inputs produces no diff.
- Unsupported manifests and failed resolution leave the original files intact,
  including cases where no lockfile existed before the command.
- An explicit directory uses that project's local dependency paths, regardless
  of the process's working directory.
